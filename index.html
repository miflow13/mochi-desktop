A desktop companion built for Linux.

Mochi is a small pixel-art character that lives on your desktop, reacts to broad local activity, works beside you, takes naps, learns emotes and builds a bond over time.

No streaks. No decay. No cloud AI. No productivity system pretending to be a pet.

What it is

A character first, software second.

Mochi is designed to feel like one coherent little creature rather than a collection of disconnected animations. Desktop events feed into a shared state and lifecycle system, so reactions enter, run and recover intentionally.

The project is open source, Linux-native and deliberately local. Context awareness is rule-based; it does not send your desktop activity to an LLM or cloud service.

Current features

v0.3 is focused on making time with Mochi feel meaningful without turning care into another obligation.

01 / Bond + feeding

Progress without punishment.

Bond grows from ordinary shared activity: typing, completed Focus time and feeding. It never decays because you closed Mochi, got busy or skipped a day.

  • No hunger meter or missed-day penalty
  • Persistent bond levels and unlocks
  • Feeding is an interaction, not maintenance

02 / Emote catalogue

New behavior has a place to live.

The catalogue keeps unlocks, rarity and animated previews in one place. Learned emotes can also join Mochi's ambient behavior pool.

  • Bond-gated emotes
  • Animated hover previews
  • Authored states instead of random GIF triggers

03 / Focus with Mochi

Quiet company while you work.

Focus sessions give Mochi a low-energy coworking state with configurable focus blocks, breaks, rounds, sparse encouragement and optional local rain.

  • Independent session lifecycle
  • Focus and break states
  • Completed time contributes to Bond

How it works

Local desktop behavior, not content collection.

AmbiSense

Mochi reacts to broad signals such as anonymous typing activity, coarse app categories, media playback, session presence, power, network and file-browsing activity.

Privacy boundary

Mochi does not collect typed characters, words, key values, document names, application titles or screen contents.

Linux-native stack

Python, GTK4/PyGObject and Cairo drive the app, with D-Bus and desktop-specific integration where the compositor permits it.

Window behavior

On GNOME Wayland, Mochi uses an XWayland GTK window where native Wayland positioning restrictions make desktop-pet placement impractical.

Portability

Better across different Linux setups.

Fedora + GNOME + Wayland remains the primary tested environment, but the installer no longer assumes every Linux desktop looks like Fedora GNOME.

Non-GNOME desktops

The optional GNOME awareness helper is skipped instead of blocking installation.

reduced integration
Python build tooling

The private environment can bootstrap the build backend it needs instead of requiring Fedora-specific build packages.

portable installer path

Automatic system dependency installation still targets Fedora. Other distributions need the equivalent runtime packages available locally. Niri, fractional scaling, multi-monitor layouts and non-GNOME sessions receive less regression coverage.

Install

Run Mochi from a clean source checkout.

The installer creates Mochi's private Python environment and adds launchers under ~/.local/bin. On GNOME, the optional awareness helper is installed when GNOME extension tooling is available.
